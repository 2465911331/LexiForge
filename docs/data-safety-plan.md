# 多词书保留进度、备份恢复与安全升级

日期：2026-09-26。状态：实施规划，尚未开发。基线：1.0.2（versionCode 3），Room 数据库版本 3。用户反馈当前功能可用；这不等同于已经验证数据迁移和备份恢复。本次不修改应用行为，不生成新版安装包。

实施进展（2026-10-04）：1.0.8 已实现多词书独立进度、学习位置、作答事件、全库备份与显式 3→4 迁移，见 [本版范围和验证](library-history-release.md)。跨词书共享与汇总队列、每日计划及正式发布加固仍待实施。下文保留最初规划，不代表当前实现；本版采用每书独立身份，未建立未经核实的跨书映射。

## 1. 目标与当前风险

目标：四级与六级词书可长期并存；换词书不丢进度；用户可自行导出、换机恢复；覆盖安装可验证地保留数据。

| 代码位置 | 已确认现状 | 本批处理 |
| --- | --- | --- |
| `data/Entities.kt` | 词条内容和复习状态混在一起，没有词书成员表 | 分离内容、词书关系、进度与事件 |
| `data/LexiRepository.kt` | `replaceWordbook()` 先删除全部词条和组件，多步操作未组成一个事务 | 改为安装词书与选择词书两个操作，失败不影响旧数据 |
| `data/AppDatabase.kt` | 数据库版本 3，`exportSchema = false` | 留存真实旧结构，导出后续结构并验证显式迁移 |
| `data/LexiRepository.kt` | 启用了 `fallbackToDestructiveMigration` | 删除自动清库兜底，失败进入数据保护页 |
| `ui/LexiViewModel.kt` | 当前词书 ID 存在偏好设置，内容另存数据库；启动时可能重装内置词书 | 将词书选择纳入数据库事务；仅在空库或明确内容更新时初始化 |
| `ui/screens/StudySettings.kt` | 切换词书与重置相绑定，没有导出、恢复入口 | 增加“我的词书”“备份与恢复”，分开危险操作 |
| Manifest、两个备份规则 XML | `allowBackup=true`，规则仍是模板 | 明确系统备份范围，不能用它替代应用内恢复 |

现有 `BuiltInUpgradeTest` 测的是同一结构内的内容修订，并未验证数据库 3 → 新结构。Room 官方说明，缺少迁移路径时启用破坏式兜底会删除数据库数据，因此移除此行为是本批发布门槛。[Room 迁移文档](https://developer.android.com/training/data-storage/room/migrating-db-versions)

## 2. 产品规则：词书独立，可靠的同一词条共享进度

沿用产品路线的默认方案，不增加让用户难以理解的“进度共享开关”。

- 四级、六级分别保留词书成员、排序、每日新词目标及启用状态。每日目标默认值属于后续学习计划设计，本批不凭空生成既往计划。
- 具有相同稳定词条身份、相同训练能力的项目共享复习状态。例如四级中已学习的同一 `transfer`，切到六级后仍显示已练习及原复习期限。
- 仅拼写相同不自动合并。不同来源、不同义项或未经审核的导入内容先保留独立身份；经内容映射核实后才能共享。不能把四级基础词义的掌握直接等同于六级新增词义的掌握。
- 首页的“本书进度”和本书训练只查询当前词书；首页另显示“其他已启用词书待复习 N 项”入口。汇总队列按学习项目去重，同一答案只更新一次状态。
- “已练习”按真实作答状态计算；暂不把它标为“已掌握”。历史学习量依据事件，不把两个词书的共享词条数量直接相加。
- 切换时只更新当前词书，已完成答案先提交；未完成题目退出、不计作答。新的界面必须同时显示新词书名称和对应数据，不能先换标题再显示旧队列。
- “移出我的词书”采用归档，停止纳入汇总复习，保留词书内容和进度，可重新启用。更新词书时移除的旧词条也归档，避免连带删除历史。
- 本批不提供“只清空某本书的共享进度”，以免影响其他词书却未告知用户。仅保留高级入口“清空全部学习记录”，范围明确、先备份、再次确认；词书和内容保留。

## 3. 数据设计与实现边界

拟采用一个 Room 数据库，结构版本暂定 4；正式编码前冻结字段与索引。保留现有调度算法，避免同时改变存储和复习规则。

| 数据对象 | 身份与职责 |
| --- | --- |
| `Wordbook` | 稳定 bookId、名称、来源、内容版本、启用/归档状态 |
| `WordEntry` / `ComponentEntry` | 稳定 entryId/componentId、教学内容、来源命名空间、审核状态与修订号；组件语义不同不能仅按名称合并 |
| `WordbookEntry` / `WordbookComponent` | 复合主键连接词书和内容，保存本书排序；组件成员显式保存，兼容旧库独立组件 |
| `LearningItem` | 连接词条或组件及训练能力；旧版词条状态先归入 `legacy_word`，组件归入 `legacy_component` |
| `LearningProgress` | 以 learningItemId 为键，保存原阶段、上次学习、下次到期、原布尔状态、已有复习次数和调度版本 |
| `ReviewEvent` | UUID 事件 ID、词书上下文、项目、训练方式、结果、辅助提示、时间、调度前后状态；与进度同事务提交 |
| `BookPlan` / `AppState` / `UserPreference` | 词书计划、当前词书及可迁移设置；与恢复的数据在同一数据库内提交 |
| `LegacyIdMap` / `OperationRecord` | 旧 ID 映射、一次性导入标记、恢复操作 ID 和完成状态，避免重启后重复导入 |

不使用释义或例句内容的哈希作为长期词条 ID，修改文本不应生成新进度。内容校验值仅用于版本判断；重新导入同一词书同一版本必须幂等。没有可靠上游 ID 的内容，由导入映射保存本地稳定 ID；存在歧义时保留两个条目并报告，不能猜测合并。

旧库没有完整作答历史，也没有区分识义与拼写能力，迁移不能编造这两类数据。旧进度逐字段保留，新版开始记录事件；统计标注“详细记录自升级后开始”。提前练习也记录事件，但继续遵守不提升复习阶段的规则。组件原有 reviewCount 保留；没有依据的单词作答次数保持未知。

所有数据写入经仓库统一入口协调。导入、切换、作答、重置和恢复不能相互穿插；界面重复点击与进程重启依靠操作 ID 和事务保护，不能只依靠一个按钮禁用状态。恢复预览后若数据已变化，提交前重新生成预览。

## 4. 先交付可恢复的备份

### 文件格式和范围

建议扩展名 `.lexiforge-backup`，内部为 ZIP，只允许 `manifest.json` 和 `data.json` 两个成员。格式版本独立于应用和数据库版本，首版为 1。

- 清单包含 backupId、formatVersion、最低读取器版本、创建时间、应用版本、来源结构版本、数据条数和 data.json 原始字节的 SHA-256。
- 数据包含全部保留的词书内容、关联、词根组件、学习状态、新版作答事件、计划、当前词书和可迁移偏好；不是只保存需要联网重新下载的地址。
- 第一批仍为单词书数据库，导出时适配成同一逻辑格式；新版读取器同时支持这批备份。旧读取器遇到超出其能力的多词书备份必须拒绝，不能只恢复其中一本。
- 保存主题、动态配色偏好、本地语音优先等设置。TTS 引擎包名仅作偏好提示；恢复后重新发现引擎，不存在则提示重新选择。系统语音引擎和离线音色文件不属于本应用备份。
- 不包含签名密钥、缓存、设备文件路径、文件授权令牌或下载中的临时内容。
- 首版为明文数据压缩包，页面直接写明“备份未加密，包含学习记录”。SHA-256 用于检测损坏，不宣称能证明来源可信；密码加密留作后续独立设计。

### 导出与恢复流程

导出：暂停应用数据写入 → 一致性快照 → 生成临时备份 → 用同一个恢复读取器校验 → 系统文件选择器选择位置 → 写入并关闭 → 重新读取校验成功后显示“备份成功”。取消、空间不足、提供方拒绝读取均不能显示成功，也不能破坏现有数据。无法重新读取的文件显示“已写入，尚未验证”，不算已验证备份。

通过 Android 的 Storage Access Framework 创建和打开备份，无需申请“所有文件访问”权限。选择云盘位置属于用户选择的文件提供方，不代表应用提供自动云同步。[Android 文件访问文档](https://developer.android.com/training/data-storage/shared/documents-files)

恢复：选择文件 → 有界解析和校验 → 预览日期、词书、进度数、影响范围 → 自动保存当前状态的恢复点 → 明确确认“用备份替换全部学习数据” → 事务提交 → 重新查询并展示结果。取消或失败保持恢复前数据。恢复页明确提示：备份之后的学习记录会被替换。

首批只实现“完整替换恢复”；合并恢复延后，不能直接取两个备份中较大的阶段或较晚的时间，因为那会丢失答错、重置与删除语义。未来合并需独立设计事件去重、冲突和删除规则。

导入文件视作不可信数据：检查大小、格式版本、重复 ZIP 成员、路径穿越、校验值、记录数量、重复 ID、外键和字段范围。首版建议限制压缩文件 50 MiB、解压数据 200 MiB、单条字符串 64 KiB、总事件 100 万条；流式读取并限制实际解压量，性能验证后调整。超限明确报错，不截断恢复。未知的更高格式或调度版本拒绝写入；非法时间/阶段拒绝并说明原因，不能静默“修正”历史。

自动恢复点保存在应用私有的非系统备份目录，只保留最近 3 份成功生成的恢复点；新备份通过校验后才轮换旧文件。生成失败就中止覆盖操作。它可用于误操作恢复，卸载或手机丢失后不可依赖，因此页面将“本机恢复点”和“已导出备份”分开显示。

### 旧结构的过渡处理

先在结构版本 3 上开发并验证导出、完整恢复及恢复点，再发布多词书结构。过渡版恢复同时涉及 Room 和 SharedPreferences，无法假装成一个数据库事务：需要持久化恢复操作记录，先保存旧偏好与恢复点，提交数据库后幂等补齐偏好；冷启动先完成未结束操作，再允许初始化词书或进入学习。必须测试两次提交之间被终止的情况。

结构版本 4 将可迁移偏好迁入 Room，旧偏好只作一次性输入；设备本地设置重新校验，不与学习状态形成半恢复状态。所有设置入口，包括发音页，都要经过统一设置仓库。

## 5. 安全升级与旧数据迁移

1. 在改实体之前保存版本 3 的真实建库 SQL、schema 和代表性数据库样本，包含内置/外部词书、错题、到期与未到期状态。启用 schema 导出并纳入版本控制；测试依赖与当前 Room 版本匹配，不借机升级存储框架。
2. 新版启动先进入数据打开状态，由应用初始化器处理迁移成功或失败，避免 ViewModel 构造时异常导致无法进入恢复页。
3. 对现有版本 3 数据，在任何内置内容初始化之前生成一致的旧结构恢复点。独占写入，正确处理 SQLite WAL；禁止直接复制一个正在写入的主数据库文件作为“完整备份”。空间不足或快照失败时停在可重试页面，不清库继续。
4. 显式实现 3 → 4 迁移，在事务内创建内容、关联与进度表，保留所有原有有效条目，不只保留 18 个内置词。
5. 由于旧词书 ID 在偏好设置里，数据库迁移先将现有内容放入稳定的“升级前词书”容器。启动后的幂等整理在数据库事务内依据已捕获的旧偏好和内容证据标记来源；缺失或冲突就保留该容器，不能错误归类为内置后覆盖。使用原偏好键映射记录，并保留旧 ID。
6. 迁移完成校验记录数、ID 映射、外键、阶段和时间，再启用新数据访问与内容更新。内容修订版本和数据库结构版本分别管理。
7. 未知旧版本、结构损坏或迁移失败时显示“原数据已保留，暂时无法完成升级”，提供重试、导出诊断和可用恢复点/备份入口；没有成功恢复点就不能展示“可恢复”的承诺。不得自动清空，也不把“卸载重装”作为默认解决办法。

当前能够直接核实的是数据库版本 3。历史版本 1/2 必须从对应源码或真实样本建立迁移，取不到样本就明确标为不支持直接升级；对于实际发布过且仍需支持的版本，缺少已验证迁移路径会阻断发布。

测试包阶段继续沿用当前包名、调试签名并递增 versionCode。公开正式包启用独立私有正式密钥，不能把仓库公开的调试密钥当正式密钥。不同签名不能假定可覆盖当前安装；默认迁移方案是使用独立正式包 ID 与测试包并存，导出 → 正式包恢复 → 核对数据后再由用户决定是否删除旧包。正式包 ID 在发布前确定，本批不擅自更名。[Android 应用签名文档](https://developer.android.com/studio/publish/app-signing)

不设计数据库降级清库。上线后发现问题优先发布更高 versionCode 的修复版；恢复点用于恢复数据，不意味着可以安全安装任意旧 APK。

系统备份规则同时覆盖 Android 12 前后格式。目标是允许持久学习数据和必要设置进入系统备份，排除临时包、恢复点和设备专属内容；系统恢复后的数据仍走同一版本校验及迁移入口。系统和厂商是否实际执行备份存在差异，应用不把它计为“最近一次已验证备份”。[Android Auto Backup 文档](https://developer.android.com/identity/data/autobackup)

## 6. 界面与按钮层级

底部导航暂时维持“今日 / 单词 / 设置”，减少本批无关改动。

- 今日顶部显示当前词书，点击进入“我的词书”。每本书显示启用状态、已练习/总数、当前到期数；主按钮为“继续学习”或“使用此词书”，归档放在更多菜单。
- “我的词书”区分已安装与可添加。下载只安装新词书，成功后才提供“切换使用”；下载失败仍可使用原词书。重新下载相同版本不重置进度。
- 设置分为“词书与计划”“备份与恢复”“外观与发音”“高级数据管理”。备份页主按钮为“导出备份”，次按钮为“从文件恢复”；最近已验证导出时间与本机恢复点各自展示。
- 恢复预览明确显示“会替换全部词书和学习记录”，不能只写“导入”；确认按钮为“替换并恢复”，取消按钮始终可见。进入不可取消的提交阶段后显示进度并禁止重复提交，进程终止依靠事务/恢复记录处理。
- 在共享进度的词条详情展示其所属词书；高级清空操作显示影响全部词书的数量。迁移、导入、恢复错误使用独立状态页或持久提示，不用短暂 Toast 掩盖失败。
- 只有完成真实校验才显示成功；总数、已练习数、到期数均来自同一数据范围和时刻，不以“100% 进度动画”代替校验。

## 7. 交付顺序

| 批次 | 可交付内容 | 进入下一批的门槛 |
| --- | --- | --- |
| A：备份过渡版 | 版本 3 结构基线；手动导出/完整恢复；本机恢复点；移除破坏式迁移兜底并提供错误入口；修复旧替换与重置的事务边界 | 当前学习数据可导出并在干净安装中恢复；异常与中断不丢数据 |
| B：多词书版 | 3 → 4 迁移；内容/进度拆分；独立词书成员和计划存储；共享身份映射；事件记录；我的词书及归档；兼容 A 的备份 | A → B 覆盖升级与 1.0.2 → B 跳版升级均通过；四级↔六级反复切换保持状态 |
| C：发布加固 | 系统备份规则；版本/签名检查；迁移链测试；恢复入口与性能优化；正式包迁移演练 | 实体机验收、故障注入与全链路测试通过，备份能独立恢复 |

不在本批同时实施云同步、备份合并、密码加密、FSRS 切换、账号系统或全新统计界面。内容许可和考试覆盖率核查继续沿用独立发布准备清单。

建议新增 `WordbookRepository`、`BackupRepository`、`MigrationCoordinator` 和统一设置仓库，拆出 ViewModel 内的下载解析。先在现有工程内形成明确边界，无需整体重写应用。各批独立生成可验收安装包和变更说明，具体版本号在打包时确定，不先承诺日期。

## 8. 验收清单

| 场景 | 必须观察到的结果 |
| --- | --- |
| 四级学 10 词 → 六级学 5 词 → 回四级 → 杀进程重开 | 原阶段和复习时间保持；共享条目正确联动，独立条目不串数据 |
| 两书包含同一确认身份的到期项目 | 汇总队列只出现一次，作答只生成一个有效事件 |
