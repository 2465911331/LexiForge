# 离线构词与内容约束

2026-09-26：维护者明确不接受调用人工智能 API，可以接受内置微型模型。本文件记录后续实现约束；尚未接入新解析包或模型。

实施进展：1.0.4 已接入首个小规模离线解析包；1.0.5 按用户要求加入词书驱动的规则推导与分块训练，未接入模型或 AI API；详见 [规则说明](morphology-rules.md)。下文的扩展方向不代表已经完成。

## 不调用 AI API

- 应用不调用云端 AI API，不要求用户提供 AI 密钥，不通过代理服务间接调用模型。
- 内容生产流程也不依赖付费或免费的云端 AI API；此前提出的 AI 批量生成草稿方案调整为规则、资料核对与人工编辑，或未来经评估的本地模型辅助。
- 已下载内容的构词查询和训练必须离线可用。GitHub 词库/内容包下载与现有在线发音是不同功能，本约束不等于禁止所有联网；它们仍遵守各自设置。

## 首选方案：原始词库加本地解析包

1. 保留上游词库，导入单词、词性、释义及实际存在的短语、例句、同根词关系。固定来源版本并核实字段含义，不把排序当词频。
2. 另行维护 LexiForge 构词解析包，记录词条映射、构词部件、拼写变化、解释、参考来源、审核状态和内容版本。
3. 使用本地词根词缀表、词族关系和明确的拼写规则生成候选。字符串匹配只产生待审核结果，不能直接成为教学结论。
4. 自动检查引用完整性、拼写还原、变化规则和冲突。1.0.5 允许通过词基、词性与例外检查的规则结果进入“拼写分块”判题，但必须标明“规则推导、未经逐词核对”，不能称为已审核词源；参见规则说明。
5. 导入时优先匹配已审核解析；缺失时保留整词拼写与词典内容。有同根词资料时可以展示词族，不强行拆解。
6. 解析包作为版本化数据发布，应用安装或更新后本地查询。修订内容与学习状态分开存储，更新不能重置复习进度。

词条身份保留来源、上游标识、词性/义项映射；仅拼写相同不自动合并。上游词义或身份发生变化时，相关解析需要重新核对。

## 可选微型模型的边界

目前不选择、不下载、不打包模型，也不承诺具体大小或准确率。只有规则与解析库无法满足需求时才评估。

- 全部推理在设备上进行，不上传单词、学习记录或设备信息；没有模型也必须可以正常学习。
- 目标优先限定为候选分段或候选排序，不要求模型自由生成词源故事。
- 模型输出仍为候选；没有经过核对不能作为正式教学或判题依据，自报置信度不能替代审核。
- 接入前核查模型与运行库的可分发条件，测量包体、内存、延迟、功耗，以及不同构词类别的准确率和错误率；未达标不引入。
- 不把“有本地模型”当作内容已正确的证据。

## 对当前工程的下一步

先移除外部导入中以文件顺序产生词频、以字符匹配直接产生构词答案的行为，接入“已审核解析 / 整词训练”的分支。随后逐步扩展解析包，不以模型上线为前置条件。现有内容修订、备份兼容和进度保留需一同验证。
