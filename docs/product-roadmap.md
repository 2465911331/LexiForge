## 产品目标

技术约束（维护者于 2026-09-26 确认）：不调用人工智能 API，也不经代理间接调用；核心构词查询和训练离线完成。优先采用本地解析库与规则，允许评估可选的内置微型模型。详见 [离线构词与内容约束](offline-content-strategy.md)。

做一款能让用户长期保存学习成果、内容可追溯、核心学习不依赖账号的 Android 开源英语学习应用。以可靠的每日学习流程对标成熟产品，以词根词族训练形成特色。

首发人群已由维护者确定：大学生四级／六级备考。优先支持 CET-4、CET-6 两套词书与各自学习计划，共享可靠词条及相应掌握状态。扩展考研、出国考试和其他语言不属于首发范围。

针对这个人群，词条应覆盖常见考纲义项、常用搭配、易混词和语境辨义；构词训练作为特色模块。词表需记录适用的大纲／参考来源、版本和覆盖映射，未核验前不能宣称完整覆盖。真题内容、考试词频与普通教学例句分别管理，来源和使用依据不清楚时采用原创教学材料，不包装为真题。

用户应能完成：选择词书 → 安排每日学习 → 学习与无提示检验 → 到期复习 → 查看真实记录 → 导出并恢复学习成果。

核心承诺目标：无需强制账号；基础学习无需付费服务；用户可以导出数据；联网服务可识别、可关闭；内容来源与版本可查询。它们是设计目标，不代表当前已全部达到。

## 当前基线

- Kotlin / Jetpack Compose 原生 Android，Room 保存进度。
- 第一批修订后，内置 18 个词、24 个组件，具备卡片、拼装、拼写和固定间隔复习。
- 第一批 18 项自动化测试通过、调试包构建成功；尚未完成实体设备验收，不能推导出学习效果优于其他产品。
- 外部词书的字符匹配拆解、按文件顺序划分词频仍待修订。
- 缺少多词书独立进度、完整作答历史和应用内可验证的备份恢复。
- 尚未发现项目许可证；内容与服务来源核查见 [开源发布准备](open-source-readiness.md)。

## 分阶段交付与验收

### A：可信基础（下一批）

范围：先建立可靠的数据和内容边界，不同时重做全部界面。

1. 分离词条、词书关联、学习状态和作答事件。相同词条跨词书默认共享学习状态，词书成员关系和学习计划独立；同形异义与不同内容来源不能仅凭拼写强行合并。
2. 增加显式数据库迁移；在写入新结构前校验旧数据，迁移失败保留原数据，不静默清库。
3. 词书导入先解析校验，再事务写入；失败不影响正在使用的词书。切换词书不重置进度。
4. 增加带格式版本的本地导出／恢复，覆盖词书、自定义内容、进度、作答事件和学习设置；恢复前预览，明确合并／替换行为，失败回滚。备份格式标明是否明文。
5. 停用未经审核的自动拆词与无依据的词频分类；缺少可信拆解时使用整词训练，缺少例句时明确显示暂无例句。
6. 给内容增加来源、授权状态、修订版本、审核状态；内容更正与学习进度分离。

验收：

- 使用旧版数据库升级，保留有效学习进度，重复升级／启动不重复生成记录。
- 学习词书 A，切换 B，再回 A，状态保持；同一共享词条不会产生冲突的复习期限。
- 导入损坏文件、重复文件或中途失败，原词书与进度保持。
- 导出到文件，在干净安装中恢复，内容、进度、事件、计划一致；非法／过新格式明确拒绝且不改变现有数据。
- 正式学习入口不再显示由字符串猜测产生的构词答案或按行号推断的词频。
- 数据库迁移、导入回滚、恢复回滚都有针对性回归测试。

### B：完整学习体验（Alpha）

- 导航采用“今日、词书、统计、设置”等明确名称；学习与复习不受早晚时段限制。
- 每日新词量可设置，到期复习单独可见，积压时允许暂停新词，不强制一次清完。
- 学习阶段可看构词和助记；检验阶段隐藏目标单词及泄露答案的提示。查看提示计为辅助作答，不计无提示掌握。
- 区分识义、拼写等能力，加入整词回忆与语境辨义；听写在设备发音条件具备时提供。
- 作答事件记录题型、结果、是否提示、用时、实际时间和调度版本；明确重复点击与重试的记录规则。
- 处理断网、发音不可用、空词书、空复习队列、进程被关闭后的恢复。
- 支持字体缩放、足够的点击区域、读屏标签，避免只靠颜色区分答案。

验收：一名新用户能完成首次学习、退出重进、到期复习和备份；作答页不泄露答案；统计可由事件重算，后续复习不改写历史完成量。选定至少一台实体手机完成全流程，另用模拟器覆盖支持的最低版本和目标版本。

### C：内容与复习深化（Beta）

- 先建立约 300 个审核词条的试用内容包，作为内容生产流程的目标规模，不宣传为完整考试词库。
- 词条包含经过核对的释义、词性、适用的构词说明、教学例句和来源；词族内容解释差异、变体与例外，避免机械生成。
- 按有依据的四级、六级词表分别核查覆盖率，区分共享基础词与六级扩展词；首个完整备考版本须覆盖对外声明的两套词表范围，不能用总词数替代覆盖率。内容审核可先完成四级基础部分，再完成六级扩展部分，未完成时明确标为试用词包。
- 评估接入有维护记录且许可证兼容的 FSRS 实现；先核查依赖、固定测试样例、历史数据转换与回退方案，再决定接入。保留当前调度作为迁移基线。
- 为首次使用、样本不足、答错、提前练习、长时间未学习和时间变化定义规则。新模型不能丢弃原始作答历史。
- 先用本地导出和系统文件选择器满足迁移；跨设备自动同步作为后续项目，独立设计冲突合并与删除同步。

验收：试用内容全部通过结构检查及人工审核；切换调度有回归测试与回退路径；真实用户完成持续试用，记录耗时、无提示正确率、复习负担与放弃原因。

### D：首个公开稳定版

- 维护者选定代码许可证，完成代码依赖和内容来源清单；不把代码许可证自动套用到第三方内容。
- 完成贡献指南、问题模板、变更日志、隐私说明、漏洞报告入口和内容纠错流程。
- 干净检出可按文档构建，持续集成执行必要测试与静态检查；不需要维护者私人配置或 API 密钥。
- 建立独立正式签名及安全备份；保持正式包签名和版本递增策略，验证上一正式版本可覆盖升级。
- 正式包不使用仓库公开的调试签名。调试包用户的数据迁移需通过已验证的备份恢复处理，不能假定不同签名可以覆盖安装。
- 公开发布内容与源码版本对应，附变更说明、已知问题及构建校验值。

发布门槛：没有已知的数据丢失缺陷；学习、复习、导入、备份恢复和升级通过实体设备验收；首发范围的内容来源清楚且覆盖声明可验证；无未处理的阻断级缺陷。测试数量和构建成功不能单独作为发布标准。

## 学习效果如何验证

软件质量与教学效果分开衡量。先确保正确运行，再验证构词训练是否值得用户投入时间。

建议在用户同意下开展小规模试用：匹配初始熟悉度、学习时间与单词难度，对比普通卡片和构词训练；在 7 天、30 天后用无提示题测回忆，另测未学过的同词族单词理解。交错／随机分配材料，记录额外练习与失访；小样本只作为迭代线索，不宣传普遍优越性。

产品观测包括：首次学习是否顺利完成、复习积压、平均学习时间、无提示正确率、备份恢复成功率和用户反馈。默认不上传逐词学习历史；如引入遥测，另行明确征求用户选择并说明字段、用途和关闭方式。

## 维护与可持续性

按数据、调度、内容、音频、界面逐步拆分现有大文件，跟随每批需求重构，不在本阶段整体重写框架。

维护者保留核心版本与内容质量责任；社区可以贡献纠错、原创例句、测试与翻译。贡献内容须注明来源和授权，未经审核不自动进入正式词库。

早期优先离线核心和本地备份，控制持续服务器成本。捐赠、赞助、可选托管同步可在后期评估；第三方内容与服务成本需独立核算，开源不意味着运行成本为零。
