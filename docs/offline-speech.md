# 离线发音修复（1.0.1）

用户报告设备：一加 Ace 2 Pro，ColorOS 16 / Android 16，系统显示 TTS Accessibility Engine。该设备未连接到开发环境；本次没有取得引擎包名、音色清单或设备运行日志，不能判定厂商引擎是否提供可供第三方应用调用的离线英语语音。

## 确认的应用问题与修复

- 缺少 Android 11+ TTS 服务的包可见性声明。补充 `android.intent.action.TTS_SERVICE` 查询，不请求查询所有应用。
- 原来创建语音对象后立即读取引擎列表并长期缓存。改为查询 TTS 服务，重新进入引擎选择／从系统设置返回时刷新。
- 原来只调用 `setLanguage(en_US)`，没有检查音色是否联网、是否待下载。现在选择英语音色，排除 `isNetworkConnectionRequired` 和 `notInstalled` 音色，优先美式、英式，再考虑其他英语变体。
- 原来只捕获构造异常，未处理异步初始化失败；训练页还会将英语不支持误报为就绪。现在等待初始化结果，限制等待时间，失败后尝试其他已安装引擎。
- 原来词表页断网仍先请求在线音频，训练页另有一套回退逻辑。现在两者共用控制器：无已验证互联网时直接本地发音，在线音频失败或超过 6 秒后回退。
- 本地发音等待 utterance 完成／错误回调，不把 `speak()` 入队成功当作已经出声。连续点击取消旧请求，离开页面／应用进入后台释放播放器和 TTS。
- 语音包安装 Intent 绑定所选引擎包名；不支持入口时提示用户在系统语音设置中检查。不将从下载页面返回误判为安装成功。

旧版厂商引擎可能没有 Voice 列表：保留英语语言兼容路径，排除明确的联网音色，传入本地合成参数。这种模式依赖引擎遵守接口约定，因此仍需飞行模式下试听；应用不能自行赋予一个云端引擎离线能力。

## 在报告设备上的验证步骤

1. 安装 `LexiForge-offline-tts-fix-debug.apk`。它沿用之前的调试签名，版本号递增为 1.0.1（versionCode 2），没有数据库结构变更。
2. 打开“设置 → 发音”，选择手机实际安装英语语音包的引擎；没有其他引擎时先选择当前的 TTS Accessibility Engine。
3. 点击“打开首选引擎的语音包页面”，核对下载的是该引擎的英语音色。原来的按钮只是系统安装页入口，不是应用内置语音包。
4. 返回应用，开启“仅使用本地语音”，点击“试听本地英语”。即使联网，这个按钮也不请求在线单词录音。
5. 开启飞行模式并关闭 Wi-Fi，调整媒体音量，再试听；随后在单词列表和学习解析页点发音按钮。
6. 若失败，记录“首选引擎”和试听结果的完整内容。提示会区分未发现引擎、初始化失败、未找到离线英语音色、合成错误和超时；系统错误码可能需要厂商进一步解释。

若当前引擎只暴露云端或中文音色，需为可供应用调用的 TTS 引擎安装英语离线数据，或使用另一款具备该能力的引擎。本版本没有捆绑第三方语音模型，不保证任意系统语音助手均支持离线英语。

## 验证边界

自动化测试通过假引擎覆盖初始化等待、联网绕过、在线超时回退、英语音色筛选、异步失败、引擎切换、取消旧请求和生命周期释放；Android 环境测试覆盖服务重新发现、安装 Intent 的目标与设置交互。它们不能替代厂商引擎的真机音频测试。
