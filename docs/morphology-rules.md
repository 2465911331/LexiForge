# 1.0.5 离线构词规则

本文记录 1.0.5；当前版本的新增规则和验证结果见 [1.0.6 说明](morphology-rules-1.0.6.md)。

本版增加词书驱动的规则推导，不调用 AI API、不下载模型。规则及中文说明由项目维护，参考通用构词与拼写规则，没有抓取或打包参考词典正文。已有解析正文与规则推导均可离线使用；参考链接需浏览器联网。

## 判定顺序

1. 先匹配已有的 18 个本地示范解析；示范词出现未识别义项时，不自动套用另一套规则。
2. 把当前词书中大小写原样为小写、仅含英文字母的词条建成词基索引，合并其词性。识别 `n.`、`v.`、`vt.`、`vi.`、`adj.`、`adv.`，支持 `a./ad.` 别名及 `n & vt.` 等组合；缺词性不猜测。词基长度限制为 3–40 个字母。
3. 在完整目标词上尝试规定词缀，同时要求当前词书存在词基、输入/输出词性符合规则。部分前缀与 `-er`/`-est` 还检查目标释义中的语义线索。
4. 先考虑最外层后缀，没有后缀候选时考虑前缀。同一优先级出现多个规则或词基候选，回退整词；不以候选排序随机选择。只拆一层，不递归发明中间词，不要求所有字母串成为词根。
5. 只应用表内的拼写变化，分块字母必须能直接连成目标词。原形与实际分块同时说明，例如 `happiness` 的词基为 `happy`，拼写分块为 `happi + -ness`。
6. 通过检查的结果标为“规则推导 · 拼写分块”，可进入分块训练，尚未经逐词核对。它不是历史词源结论，也不能保证词缀的一般意义等于整个词的释义。没有合适候选的词继续整词拼写。

这是对 1.0.4 仅示范解析能拼装的扩展。规则提供的是可解释的拼写练习；已核对解析与规则推导在界面中明确区分。

## 拼写变化与例外

- 直接拼接，例如 `care + -less`。
- 指定后缀前，辅音后的 `y → i`，例如 `happy → happi + -ness`。
- 指定元音后缀前去掉末尾 `e`，例如 `make → mak + -ing`。
- `-ing/-ed/-er/-est` 可能出现末尾辅音双写，例 `run → runn + -ing`。通过已存在的目标词与词基反向识别，不根据字母猜测重音。另有常见必须双写的动词表，避免把 hoping 推成 hop + ing。
- `ie → y`，例 `lie → ly + -ing`。
- `-le → -ly` 与有限去 e 的副词，例 `simple → simp + -ly`、`true → tru + -ly`。
- `-ble → -bil + -ity`，例 `possible → possibil + -ity`。
- 名词复数只覆盖表内 `-s/-es/y → i` 模式，不处理不规则复数。
- 显式排除 business、hardly、flower、reply、resign、understand、news 等容易误导的词。真实词书检查还排除了 legal/leg、mineral/miner、formation/format、compliment/comply、liable/lie 等同形干扰，以及把 electronics 等学科名词套成一般复数的情况。例外表需要持续维护。

## 更新、恢复与进度

升级首次启动和恢复备份时，使用当前词书重新运行规则。不用重新下载词书，单词 ID、释义和学习期限不变，原有受保护更新流程先创建恢复点。重复更新不会重置进度。

规则组件使用独立 `rule:` 标识，不与已有词源组件混淆；词基原形及实际拼写写入标识，并在展示、判题前重新验证。词基仍沿用现有数据库 ROOT 类型，但学习页和卡片明确标为“词基 BASE”，首页入口统一为“构词部件”。备份格式和 Room 数据库版本不变。旧的无效组件记录保留作备份档案，不作为新单词答案；已不被词条引用的规则组件不进入练习队列。

## 局限与扩展方式

这是通用规则启发式分析，不是逐词人工校对词典。词基缺失、上游词性缺失、语义线索不匹配、候选冲突都会减少覆盖；一词多义、偶然同形仍可能造成误推导。没有承诺拆解整个词库，也没有把词频与形态复杂度混为一谈；词频仍未分级。

本批未加入希腊/拉丁词根推断、无限多层拆解、连字符复合词、专名或模型。扩大覆盖应优先完善词性读取、词基资源和例外表，再加带正反例测试的新规则。当前使用同一词书的词基，不额外打包来源不明的词典。
